# idictation-read

爱听写（idictation.cn）雅思阅读真题的自动作答

## 使用方法

- **Windows**：双击 `start.bat`
- **macOS / Linux**：`./start.sh`（首次要 `chmod +x start.sh`）

启动器会自己把该装的装好：没 Node 就装 Node，没浏览器就用 Edge 顶替，然后弹出浏览器让你登录

你要做的只有三步：

1. 在浏览器里登录，进入任意一套雅思阅读真题
2. 回到黑窗口按一次回车
3. 输入目标正确率（0~1，比如 `0.9` 表示 40 题错 4 题），直接回车用默认 0.9

它会从地址栏读出试卷编号（`read-jj?...id=90` 里那个 90），自动拉答案、生成划线批注、分批提交，最后交卷

用时不用你管，每次在 45~55 分钟之间随机取一个值

## 它做了什么

1. 调 `jijing/test/show/{id}` 拿题目，响应里带着 `display_answer`（正确答案）和 `key_locating_words`（定位词），三篇一次全给
2. 整理成 `{type,id,group_id,answer}` 结构，按批提交到 `yuedu-zhenti/v1/submit`
3. 每批的 `duration` 沿时间轴递增
4. 最后带 `action: "手动提交"` 提交

## 关于答题时长

`duration` 是客户端上报的值，服务端拿它算剩余时间（进答题页时倒计时显示的就是 60 分钟减去 duration），不校验真实耗时，成绩记录里显示的是设定好的 45~55 随机时间

## CLI用法

启动器用的是默认参数，想改就自己调：

```bash
node src/read.mjs --cdp "ws://127.0.0.1:9222/devtools/browser/xxx" --test 90 --accuracy 0.9
```

| 参数 | 说明 |
|---|---|
| `--test <id>` | 试卷 ID，地址栏 `read-jj?id=` 后面那个数字 |
| `--accuracy <0~1>` | 目标正确率，0.9 表示 40 题里故意错 4 题，错哪几道每次随机 |
| `--minutes-min` / `--minutes-max` | 总用时区间，默认 45~55 分钟 |
| `--batch <n>` | 每批提交几题，默认 8 |
| `--dry` | 只解析答案并打印计划，不发任何请求 |

先看计划再决定要不要跑：

```bash
node src/read.mjs --cdp "..." --test 90 --accuracy 0.9 --dry
```

`--cdp` 的值来自 `http://127.0.0.1:9222/json/version` 里的 `webSocketDebuggerUrl`

## 题型适配

平台阅读题共有 13 种题型分支，实测覆盖 12 种：

| type | 什么题 | 答案格式 | 状态 |
|---|---|---|---|
| 1 | 判断题 | `T` / `F` / `NG` / `Y` / `N` | 已验证 |
| 2 | 匹配题 | 字母 `A`~`Z` | 已验证 |
| 3 | 匹配题 | 字母 | 已验证 |
| 4 | 填空题 | 文本 | 已验证 |
| 5 | 单选题 | 字母 | 已验证 |
| 6 | 段落标题匹配 | 罗马数字 `vii` / `ix` | 未实测 |
| 7 | 多选题（拖拽） | **数组** `["B","C","E"]` | 已验证 |
| 8 | 填空题 | 文本 | 已验证 |
| 9 | 匹配题 | 字母 | 未实测 |
| 10 | 匹配题 | 字母 | 已验证 |
| 11 | 填空题 | 文本，多个可接受答案用 ` / ` 分隔 | 已验证 |
| 12 | 填空题 | 文本 | 已验证 |
| 13 | 匹配题 | 字母，可能是 `A,B` 多值 | 未实测 |
